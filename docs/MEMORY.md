# MEMORY — Build Log

A dated record of what was built, in what order, and what was wrong with it.
Every milestone carries a **criticism** section, because a log that only records
successes is not useful for deciding what to fix next.

Dates are commit dates. Commit hashes are on `master` of `axzss/autooverlay-ai`.

---

## 2026-08-25 — Day 1: foundation

### `9586e31` — Initial scaffold
**89 files, +12,110 lines.**

Created the project skeleton: FastAPI backend, Next.js frontend with five page
routes, agent package layout, mock data fixtures, and a Tailwind design system.

This repo is itself a **recovery artefact**. The predecessor repo
(`alpaca-overlay-agent-a2z`) had a live Alpaca API key committed into its git
history. It was scrubbed with `git commit --amend` + `git gc --prune=now
--aggressive` + force push, and a fresh clone was verified to contain no
secrets. Rather than trust a rewritten history in front of judges, this repo was
started clean via `rsync` excluding `.git`, `node_modules`, `.next`, `.env`.

**Criticism.** Most of those 12,110 lines were UI mockups with hardcoded data,
not working software. Several of those mockup components are *still* in the tree
today (see `KNOWN-ISSUES.md`) and one of them displays a fabricated executed
trade. Scaffolding at that volume created a debt that was never fully repaid —
a smaller skeleton wired to real data from day one would have been honest sooner.

### `edc76ff` — Real Alpaca integration, strategy engine, QA suite
**19 files, +1,748 / −194.**

Four parallel subagents: backend wired FastAPI routes to the Alpaca paper API
with env-only credentials and mock fallback; AI engineer implemented
`covered_call.py`, `cash_secured_put.py`, `decision_engine.py`; frontend wired
Dashboard and Assets to live endpoints; QA created the first test suites
(34 tests).

**Criticism.** Parallelism bought speed and cost coherence. The frontend wired
*some* components and left others as mockups, with no record of which was which
— the exact ambiguity that resurfaced three days later as "the Run Agent button
does nothing". A written contract of which components were live would have cost
minutes and saved hours.

### `39721f4` — Exit management, portfolio risk context, reasoning traces
**8 files, +664 / −4.**

`exit_manager.py` (take-profit 60%, stop-loss 200%, roll on |delta| > 0.40 or
DTE < 7), `portfolio_analyst.py` (25% per-ticker concentration cap, 10% cash
reserve floor), and `reasoning_trace` on every recommendation.

**Criticism.** The 60/200 asymmetry looks wrong to anyone reading it cold and
was questioned. It is correct for premium selling — you collect a small credit
with high win probability, so you take profit early and cut losses late relative
to the credit — but it shipped with no explanatory comment. Non-obvious
parameters need their rationale written next to them.

## 2026-08-26 — Day 2: making it real

### `bfe7ff6` — Configurable strategy parameters end-to-end
**12 files, +582 / −35.**

`agent/config.py` with a `StrategyConfig` dataclass, `GET/PUT /strategy/config`,
and a settings UI card. Overridable via `STRATEGY_CONFIG_JSON`.

**Criticism.** The env-var override became an attack surface (finding S6 in the
security review) and had to be hardened later. Making something configurable and
making it *safely* configurable are separate pieces of work; only the first was
done here.

### `f7a21af` — Neutral mock account id
Replaced a real paper account id (`PA3CBCJTGBJS`) that had leaked into three
mock JSON files with `MOCK_ACCOUNT_1`.

**Criticism.** Mock fixtures were generated by dumping real API responses, so
they inherited real identifiers. Not a credential, but it shows fixture
generation had no sanitisation step. It still has none — it just has no known
leaks.

### `51c4528` — Alpaca auth header fix
`APCA-API-SECRET` → `APCA-API-SECRET-KEY`. Every live trading call had been
returning 401.

**Criticism.** This bug survived a full day because the mock fallback was too
good: with no credentials the app looked healthy, and with bad credentials it
*also* looked healthy because it silently fell back to mock. Graceful
degradation without a visible signal hides bugs. This is the direct ancestor of
the `live_error` surfacing added two days later.

### `9af65ce` — Full-stack agent workflow, live Terminal
**8 files, +786 / −12.**

Terminal page with agent activity feed, reasoning-trace display, and the
decision engine wired into `/strategy/screen` via a `full` parameter.

### `a5458a5` — Isolate screen tests from real credentials
Tests were reading `ALPACA_KEY` from the environment and hitting the live API —
non-deterministic, and they would have failed in CI. Fixed with an autouse
`monkeypatch` fixture forcing mock mode.

**Criticism.** Tests that pass only on the developer's machine are worse than no
tests, because they create false confidence. This should have been the *first*
fixture written, not a patch three days in.

### `e488864` — Investment Council: six personas
**11 files, +1,398 lines.**

`agent/council/` with `personas.py` (Buffett, Munger, Dalio, Graham, Lynch,
Wood), `engine.py` (consensus + dissent detection), `report.py`, and
`risk_mitigation.py` (kill-switch). Ran against real Alpaca market data for
8 symbols and produced `docs/council_report.md`.

**Criticism — the important one.** All 8 symbols came back **HOLD
(LOW-CONFIDENCE)**, because the personas needed fundamentals (P/E, dividend
record, current ratio) and the only available data was price and volatility. A
committee of six investors that unanimously says "not sure" about everything is
theatre, not analysis. The council was structurally complete and
epistemically empty. Fixing this required the fundamentals layer, two days later.

### `fd006af` — Council → AI Engineer handoff
**7 files, +883 / −20.**

`handoff.py` parses the council report's HANDOFF section into a structured
`TierPolicy` (volatility tiers: low <20%, mid 20–35%, high >35%; per-tier delta
bands, DTE limits, size multipliers; TSLA override delta ≤ 0.10). The decision
engine consumes it, enforces a 40% tech-sector cap, and blocks non-compliant
candidates with traces citing the council section.

**Criticism.** The handoff parses **markdown with regex**. Any change to the
report's formatting silently degrades the policy to defaults, and the council's
intent is lost without an error. This later became security finding S5 (a
crafted report could inject `delta 0.99`), which was clamped — but clamping an
injection is not the same as having a trustworthy channel. A structured
side-channel (JSON emitted alongside the report) remains the correct fix and is
still open.

### `72af5b0` — Penetration test fixes
**8 files, +405 / −27.**

A red-team subagent attacked a locally running instance and found 7 issues:

| ID | Sev | Finding | Fix |
|---|---|---|---|
| S1 | HIGH | NaN/Infinity accepted by `PUT /strategy/config`; NaN comparisons return `False`, silently disabling every threshold | Explicit finiteness validation |
| S2 | MED | `stop_loss_mult: 1e308` accepted | Magnitude bounds |
| S3 | HIGH | NaN qty / Infinity limit_price → HTTP 500 | Pydantic bounds on trade route |
| S4 | MED | `top_n=-1` / `1e9` → HTTP 500 | Bounds on screen route |
| S5 | HIGH | Handoff markdown injection | Schema sanitisation, delta ≤ 0.95, DTE ≤ 365 |
| S6 | MED | `STRATEGY_CONFIG_JSON` hostile types crash loader | Type validation + fallback |
| S7 | INFO | Frontend rendering | Already safe, no change |

Plus 32 regression tests. Every previously-successful exploit now returns 422 or
a clamped value.

**Criticism.** S1 is the one that should worry us. A NaN threshold does not
throw — it makes every `>` and `<` comparison return `False`, so the kill-switch
and every risk cap turn off *silently* while the UI still shows them as active.
That is the worst possible failure mode in a trading system, and it existed
because config was validated for type but not for value. The residual
recommendation from the red team — cryptographically sign the council report
before trusting its HANDOFF section — is still unimplemented.

### `21685e0` — Council web page
**15 files, +1,366 / −60.**

`GET /council/assess` and a `/council` page: per-ticker cards, tier badges,
consensus gauge, expandable persona verdicts, amber dissent highlights.

### `da5d494` — The Intelligent Investor analysis
**1 file, +32.**

Downloaded Graham's *The Intelligent Investor* (Zweig commentary edition, 708
pages) and extracted the full text. Two of three provided sources returned HTTP
403; the third worked. Distilled into `graham_principles.py`: the seven Ch.14
defensive tests, Ch.20 Margin of Safety, Ch.8 Mr. Market. Rewrote the Graham
persona to score against the **real** criteria, citing which test fails in each
bullet. Added `mr_market.py`. Appended a "Graham Principles Audit" to the
council report.

**Criticism.** Four of the seven tests need 10–20 years of history that free
data sources do not reliably supply, so they returned INCONCLUSIVE — and at this
point INCONCLUSIVE counted as *neutral*, which quietly biased the council
**bullish** on exactly the names with the thinnest data. Being rigorous about
the criteria while being sloppy about missing data produced a worse result than
being uniformly crude. Fixed two days later by weighting INCONCLUSIVE as a
half-fail. The book text and PDF are gitignored (copyright); only short
paraphrases appear in comments.

## 2026-08-27 — Day 3: orchestration, and a revert

### `40c5805` — Daily cycle orchestration
**7 files, +1,552 / −1.**

`agent/council/daily_cycle.py`: kill-switch first (if halted, return
immediately), then snapshots + fundamentals, Mr. Market mood from SPY, council
assessments, exit evaluation on open overlays, new-entry screening with tier and
sector caps, and a prioritised `DailyDirective` queue where each item carries
`reasoning_trace` and `provenance` (e.g. `council §6`, `graham test 4`,
`tier:mid`).

Two tests failed on arrival and were fixed here. Root cause in both cases was
the *test*, not the module: `daily_cycle` evaluates every symbol in `wanted`, so
a test asserting "the INITIATE is MSFT" broke when SPY was also a candidate;
and SPY must be present in the snapshot pool for Mr. Market to have a market
proxy at all.

**Criticism.** The subagent that wrote this hit its iteration cap mid-run and
returned an incomplete report, leaving the frontend panel unbuilt and two tests
red. Work was pushed only after the failures were understood — but the episode
shows a structural weakness: a subagent's self-report is not evidence. Every
claim in this log that says "verified" was re-run locally.

### `3eb6e0d` — Timeout/retry, trace normalisation, overlay drawdown
**6 files, +316 / −20.**

Daily Cycle UI panel; `fetch_timeout_seconds` / `fetch_retries` with fallback to
bundled snapshots; `_normalize_trace()` guaranteeing `list[str]`;
`overlay_only_drawdown` so the kill-switch measures drawdown on overlay capital
rather than whole-portfolio NAV.

**Criticism.** `overlay_only_drawdown` fixes a real false-positive — a large
equity portfolio moving normally could trip a 5% halt that has nothing to do
with the overlay — but it defaults to `True`, which means the kill-switch is now
*less* sensitive by default than the documentation implied for two days.
Loosening a safety control deserves louder announcement than it got.

## 2026-08-28 — Day 4: a revert, and honest wiring

### Reverted batch (`a7b475f`, then `git reset --hard` + force push)

Two parallel subagents delivered fundamentals enrichment (Yahoo Finance
cookie+crumb handshake, 24h persistent cache, `data_age_hours`/`stale` flags),
Mr. Market hysteresis, Graham INCONCLUSIVE-as-half-fail, and the frontend
endpoint wiring. Tests went 236 → 265. Measured effect of the Graham
re-weighting: SPY/QQQ −1.2, NVDA 68.0 → 67.6, JPM 52.0 → 51.6.

It was committed, pushed, and then **removed from history entirely** at the
user's instruction.

**Criticism — this is the process failure worth remembering.** The commit was
made from a subagent's summary without reading the full diff first. Two files
were changed that were never in the brief: `next.config.js` (proxy rewrite) and
`Sidebar.tsx` (layout `fixed` → flex child). Neither was mentioned in the report
to the user. The user spotted it immediately. The work itself was largely
correct — the proxy rewrite was a genuine bug fix, later re-applied
independently after being verified — but scope discipline matters more than
being right. Trust is the constraint, not correctness.

Two consequences now hold as rules: **read the diff before committing**, and
**report every changed file, including ones you think are trivial**.

### Uncommitted at time of writing — dashboard layout fixes
Content was rendering *behind* the fixed sidebar: `Sidebar` uses `fixed
inset-y-0 left-0 w-[240px]`, so it leaves the document flow, but the content

wrapper on all five pages (`lg:` only — below that breakpoint the sidebar is

## Standing criticisms not yet resolved

1. **Fundamentals are ephemeral.** The cache lives in `/tmp`. A restart drops
   the council from HIGH to LOW confidence and reverts NVDA/MSFT to HOLD. The
   fix was written and then reverted; it needs redoing.
2. **Mockup components still render.** `ThoughtProcess.tsx` displays a
   fabricated executed trade with a fabricated $120 yield. It is the single
   biggest credibility risk in a live demo.
3. **`_order_intents` cannot produce a real contract.** It reads
   `option_symbol` and `limit_price` from directive params, but `INITIATE`
   directives carry tier policy, not concrete contracts — so both are always
   `null` and `type` always falls back to `"market"`.
4. **`specials/BACKEND_FRONTEND_API.md` contradicts the code** on `tier`,
   `consensus_score` scale, and `delta_min` sign. See `KNOWN-ISSUES.md`.
5. **Handoff trust.** Markdown parsing with regex, clamped but not
   authenticated. The red team's provenance-signing recommendation is open.
6. **No visual verification, no E2E test.** Nobody has confirmed the UI renders
   correctly, by eye or by automation.
